# 결정 기록

## D1. 새 저장소·새 DB로 따로 (2026-10-22)
미국 전용이라 로그인·결제·발송·언어·약관이 BZR과 전부 다르다. 한 저장소에 섞으면 한국 손님 결제·카톡 발송이 깨질 위험이 있어 완전히 분리. BZR의 검증된 부품(DB 연결, HTTP 도우미, 테스트 DB, 점검 방식)은 복사해 와서 쓴다.

## D2. 화면은 BZR처럼 정적 HTML + API
BZR과 같은 방식이라 관리·이해가 쉽고 빠르다. 디자인도 BZR 것을 그대로 따른다 (사장님 지시).

## D3. 사주 계산은 서버 한 곳(lib/saju.ts)
- 일주: 율리우스 일수 계산 (만세력 라이브러리와 2만 8천 시점 100% 일치).
- 년주·월주: 태양 황경(astronomy-engine)으로 절입 시각까지 계산. 라이브러리는 날짜 단위라 절기 당일 몇 시간만 다를 수 있다 (우리 쪽이 더 정확). 라이브러리는 일부 12월 31일 년주를 틀리게 내는 버그가 있어 대조에서 제외.
- 23시대 출생도 날짜는 바꾸지 않는다 (생일만 넣은 결과와 같게, 라이브러리와 같은 방식).
- 생일만 받을 때는 출생지 기본값을 미국 동부(UTC-5) 정오로 본다. 계절 경계 하루 정도만 영향.
- 화면에서 따로 계산하지 않는다 → 계산 규칙이 한 곳.

## D4. Korean sign = 일간 × 계절 (40가지)
미국 사람은 MBTI처럼 "타입"을 좋아하고 공유한다. 일간 10개만 쓰면 너무 겹치고, 계절을 섞으면 40개로 적당히 다양하다. 계절-일간 관계로 "In season / Season-fed / Off season"(득령) 한 줄을 더해 사주다운 근거를 보여 준다.

## D5. 관계 이름은 우리가 새로 지음
오행 생극 5관계 → Mirror(비겁) / Battery(인성) / Spark(식상) / Co-pilot(재성) / Coach(관성). 국내 비슷한 서비스의 이름을 쓰지 않는다.

## D6. 로그인 전 단계의 지도 주인 확인 = 비밀 토큰
지도를 만들 때 주인 브라우저에만 비밀 토큰을 주고 DB에는 해시만 저장. 로그인(구글·애플)을 붙이면 지도를 계정에 연결한다. 토큰을 잃으면 지우기만 못 할 뿐 지도는 그대로 (백로그: 로그인 후 계정 연결).

## D7. 친구 정보 공개 범위
친구의 생일은 저장하지만 어떤 API도 돌려주지 않는다. 지도에는 별명·타입·관계·점수만. 친구가 "지도에 올리기"에 동의(기본 체크, 끌 수 있음)했을 때만 저장하고, 안 하면 결과만 보여 주고 아무것도 저장하지 않는다.

## D8. DB는 Vercel 연동 Neon Postgres (무료, 미국 동부)
Supabase 무료 플랜은 활성 프로젝트 2개까지이고 이미 bzr·maeil-gukeo가 있다. 유료($25/월)·새 계정 대신 사장님이 Vercel Storage에서 Neon(무료)을 붙였다. Vercel이 DATABASE_URL 등을 자동으로 넣어 준다.
- 스키마는 그대로 `supabase/migrations/*.sql`. Neon에는 Supabase의 화면용 역할(anon·authenticated)이 없어 migration은 그 역할이 있을 때만 권한을 막는다. 화면은 어차피 DB에 직접 붙지 않고 서버 API만 쓴다.
- 배포 빌드 때 `scripts/db-migrate.mjs`가 아직 안 넣은 migration만 순서대로 적용 (`schema_migrations` 표에 기록, 동시 배포 잠금). 비밀 값은 채팅·로그에 나오지 않는다.
- 로그인은 Supabase Auth 대신 다른 방법(구글 로그인 직접 또는 Auth.js)으로 붙인다 → 그때 결정 기록.

## D9. 출생 시각은 무료 단계에서 "선택", 상세 리포트에서 "필수"
사주는 시주까지 있어야 완성이고, AI 리포트는 서버가 계산한 네 기둥을 넘겨야 흔들리지 않는다(사장님 지적). 다만 친구 입력은 쉬워야 퍼지므로 무료 단계에서는 선택으로 받되, 넣으면 네 기둥 표를 보여 줘서 넣을 이유를 만든다. 상세 리포트에서는 시간·출생지를 필수로 받고, 모르는 사람은 "시간 모름"을 명시해 AI에게 시주 없음으로 넘긴다.

## D10. 결제 전에는 상세 리포트 "예약"으로 수요 확인
Paddle 가입 전이라 결제는 못 받는다. 버튼을 막아 두는 대신 실제 신청(이메일 + 차트 정보)을 받아 `reading_requests`에 저장하고 "청구 없음, 결제 열리면 이메일"이라고 정직하게 안내한다. 몇 명이 $9.99에 손을 드는지가 곧 수요 시험이 된다. 같은 이메일은 한 줄로 갱신.
